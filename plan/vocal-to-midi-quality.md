# 人声转 MIDI 质量升级实施计划

日期：2026-09-06

状态：实施中。P0、P1 与 P1.5 已完成；GAME medium 能明显改善起音检测，但阈值和 D3PM 步数调优仍不能改善严格起止指标。默认引擎保持 Basic Pitch，下一步提前进行 P3 的连续 F0 边界诊断。真实混音及 Demucs 残留覆盖仍待补充，尚未证明真实歌曲识别准确率提高。

## 1. 目标与边界

保留目前效果较好的人声分离，减少后续转录中的漏音、错误切分、误合并和量化损失。
优先支持单一主唱，产出两种可比较结果：忠实于演唱时间的 MIDI，以及便于演唱、演奏和阅读的量化谱。

- 保留原始连续音高、发声置信度、未量化音符及各阶段结果，不能只保存最终谱面。
- 保留真实重复音、换气、跳进和装饰音；不以“更连贯”为理由强行填满休止符。
- 合唱、多主唱重叠和完整多乐器总谱不作为本轮保证支持的场景。
- 不首先训练大模型，也不首先开发完整的可微分合成反演系统。
- 项目用途为非商业、GitHub 公开开发。权重不进入 Git；第三方许可按 [许可清单](../docs/model-licenses.md) 单独审查。

## 2. 当前基线与待验证问题

现有链路为 Demucs / 本地中心声像提取 → Basic Pitch → 主旋律整理 → 量化 → 谱面。
已有后台取消、本地推理 Worker、原曲与分离人声试听、`raw_notes` 恢复及 revision 保存。

当前可能造成损失的位置，需用真实片段验证而不是先认定根因：

1. 通用复音模型对歌声的颤音、滑音、辅音和重复同音符边界识别不准。
2. 短于 60ms、低置信度或超出默认音域的候选被过滤。
3. 连续性惩罚压掉真实跳进或短装饰音。
4. 四分之一拍网格使不同起点重合，随后去重进一步丢音。
5. 单一 BPM 和过早量化无法准确表示自由速度与细微时值。

现有 `raw_notes` 保留了秒级来源时间，但不是完整的帧级模型输出，不能当作无损声学证据。
早期项目缺少原始检测结果时必须重新识别；不从整理结果虚构“原始数据”。

## 3. 模型选型与约束

| 项目 | 本轮角色 | 进入条件 |
|---|---|---|
| [GAME](https://github.com/openvpi/GAME) | 优先候选：歌声音符及边界预测 | 固定官方权重、确认非商用条款；先测 small/medium 的本机质量与资源成本 |
| [SOME](https://github.com/openvpi/SOME) | 轻量、CPU 对照 | 独立环境可复现运行，记录权重 CC BY-NC-SA 4.0 条件 |
| [ROSVOT](https://github.com/RickyL-2000/ROSVOT) | 可选第二批对照 | GAME/SOME 在中文或残留噪声片段上仍明显不足，且完成权重授权核查 |
| [RMVPE](https://github.com/Dream-High/RMVPE) | 独立连续基频与发声校验 | 固定原实现或[部署实现](https://github.com/yxlllc/RMVPE)，确认权重授权和 CPU/GPU 可运行性 |
| [Basic Pitch](https://github.com/spotify/basic-pitch) | 保留原始输出基线与回退 | 固定当前版本，不在模型对比中混用不同后处理参数 |
| [DDSP](https://github.com/magenta/ddsp) | 远期可选，谐波与频谱对照 | 仅在特征级校验证明有效但不足后启动；另立实验，不阻塞主线 |

GAME/SOME 的代码 MIT 不等于权重 MIT；所调研官方权重为 CC BY-NC-SA 4.0。
非商业用途符合选型方向，但仍必须落实署名及适用的相同方式共享要求。未知授权必须先核实。
ROSVOT 和 RMVPE 不因代码可下载就自动通过权重审查。

## 4. 目标流水线与数据契约

```text
已分离人声
  ├─ Basic Pitch / GAME / SOME → 未量化候选音符、边界证据
  └─ RMVPE → 连续 F0、发声掩码及可用的置信信息
             ↓
      对齐、差异标注、受约束的局部修正
             ↓
      演唱版 MIDI（秒级时间、可选 pitch bend）
             ↓
      独立节奏量化 → 演奏版 MIDI / 五线谱 / 简谱 / MusicXML
```

建议扩展现有适配器输出，而非破坏当前 `MelodyTranscriber` 的回退能力：

- 音符：原始起止秒数、连续音高（若模型支持）、整数 MIDI、模型提供的置信信息、来源 ID。
- 帧级轨迹：时间、F0、voiced/unvoiced、可用置信信息；缺失值明确记录，不编造置信度。
- 谱面音符与源候选使用来源映射；记录删除、合并、补音、移调、边界调整的原因。
- 大型帧级数组作为独立文件存储，项目 JSON 只保存对象键、版本、摘要与计数。
- 记录模型及代码版本、权重哈希、语言、参数、随机种子（如适用）、设备和耗时。
- 原始检测、局部修正、量化三个版本独立保存；用户编辑不被后台实验覆盖。
- 字段通过可选扩展保持旧项目兼容；涉及持久化结构变更时提供迁移和降级测试。

## 5. 分阶段实施

### P0：许可登记、基线与损失定位

- [x] 固定当前代码基线与处理参数，建立模型和权重清单，更新 README 接入状态。
- [x] 选取经授权人声。已纳入 Vocadito 全部 40 段并覆盖双标注、不同语言和音域；真实混音及残留和声另行补充。
- [x] 导入 A1/A2 音高和音符起止标注，以标注分歧生成不确定区域；按歌手划分 25 段 tuning 和 15 段 holdout，无歌手泄漏。
- [x] 分别导出原始检测、整理后、量化后的结果，定位每一步删改的音符。
- [x] 增加诊断开关：关闭短音过滤、连续性处理、固定音域限制或量化，逐项消融比较。

产物：评测 manifest、标注规范、基线报告、损失分布和固定验收阈值。
验收：能指出哪些错误来自模型、整理或量化；可重复生成同一报告；无未授权音频入库。

### P1：歌声专用模型小样本对比

- [x] 以固定 commit 的独立 CPU 容器运行 GAME 和 SOME，未修改当前 Worker 依赖。
- [x] 在相同 40 段 Vocadito 上比较 Basic Pitch raw、GAME small/medium 和 SOME。
- [x] 使用统一格式比较未量化音符；未为候选单独改变评测容差或后处理。
- [x] 记录质量、CPU 耗时、峰值内存、加载时间、失败率和容器取消实测；当前 Docker 无 GPU runtime。
- [x] 固定随机种子 `114514`，GAME 固定 D3PM 8 步和默认阈值。

产物：可复现的实验命令、统一格式结果、逐片段对照报告、推荐引擎与资源预算。
验收：在保留测试集上达到 P0 预先登记的质量门槛，且漏音、误切与人工修谱成本均无不可接受回归。
若不达标：保留现有默认引擎，把候选留在实验模式，不以宣传数据代替实测。

P1 验收结论：未通过。GAME medium 的 holdout 起止 F1 相对 Basic Pitch raw 提高 `0.0492`，但 recall 仅提高 `0.0286`，未达到 `0.05` 门槛；SOME 的 F1 和 recall 增幅也未达标。GAME/SOME 均不能及时响应容器停止。详见 `evaluation/reports/vocadito-candidate-comparison.md`。

### P1.5：GAME tuning 诊断

- [x] runner 支持显式 split、presence/boundary threshold、D3PM 步数和 language ID，并把参数写入 runtime。
- [x] 只在 25 段 tuning 上比较 6 组阈值；未使用 holdout 选择参数。
- [x] 阈值网格失败后增加一次 16-step 诊断；结果与 8-step 完全相同。
- [x] 按预先写入机器配置的 precision、失败率、F1 和 recall 规则选择；所有配置均未通过 tuning 门槛。
- [x] 明确区分起音检测与严格起止匹配：最佳配置的起音 F1 为 `0.6305`，起止 F1 仅 `0.3041`。

产物：`evaluation/game-tuning-grid.json`、`evaluation/reports/vocadito-game-tuning.json`、诊断报告和可恢复运行脚本。
结论：presence `0.10` 至 `0.20` 几乎不影响 recall；boundary `0.10` 仅带来小幅改善；增加 D3PM 步数无收益。停止 GAME 参数扩展，不运行 tuned holdout，不以当前数据微调。先用连续 F0/发声区间验证局部止音校正，再决定是否接入实验引擎。详见 `evaluation/reports/vocadito-game-tuning.md`。

### P2：接入候选引擎与原始结果保真（等待 P3 诊断）

- [ ] 将胜出候选接到后端转录适配器，复用任务取消、进度、错误状态和隔离子进程。
- [ ] 支持显式选择引擎；模型不存在时显示安装/配置错误，不静默伪装为另一个模型。
- [ ] 实现带校验的权重获取说明或脚本；默认不把权重打包进源码、Release 或公共镜像。
- [ ] 保存未量化结果及模型提供的边界/连续音高，保持 `raw_notes` 恢复兼容。
- [ ] 按乐句或静音分段处理长音频，校验重叠区域的时间偏移、漏音和重复音。

验收：完整任务可取消、重试、恢复，旧项目仍能打开；结果可追溯到固定模型；切回 Basic Pitch 不丢用户编辑。

### P3：连续音高校验与可解释局部修正（下一阶段）

- [ ] 接入 RMVPE，生成与原人声同一时间轴上的 F0 和发声区间。
- [ ] 先做诊断：疑似漏音、八度错误、多切、误合及无声区误报，并显示相关时间段。
- [ ] 将候选音符展开成时间轴，与可靠 F0 区域比较；音高比较使用 cents 等音程距离。
- [ ] 自动修正默认关闭；先由用户逐项接受，保留撤销与修改原因。
- [ ] 仅在多种证据一致时尝试局部增删、移调、合并或拆分；设置最大改动范围，防止级联改写。
- [ ] 同音高重复音必须结合起音/边界证据判断；歌词边界可选，不能假设一个字对应一个音符。

验收：降低人工确认的漏音和八度错误，同时不过度增加误补音、误合并；低置信和声区域只提示、不强制修改。
RMVPE 也是模型，其错误不能被当作绝对真值。校验损失降低不等于真实谱面一定更正确。

### P4：演唱版与谱面版分离

- [ ] 演唱版保存秒级起止、微小时间偏移和可选 pitch bend；颤音不自动拆成多个谱面音符。
- [ ] 谱面量化作为独立、可关闭步骤，提供网格/强度及三连音等节奏候选。
- [ ] BPM、节拍偏移不准时先允许人工修正；变速曲不强制挤入单一固定速度。
- [ ] 量化冲突显式提示或保留候选，不再默认按同起点只留一个音符。
- [ ] 界面叠加 F0、候选音符和量化音符，支持片段循环及人声/谱面试听。
- [ ] 导出明确选择演唱版 MIDI 或谱面版 MIDI；MusicXML/五线谱/简谱使用谱面版。

验收：切换谱面量化不能改变原始识别；重复量化不累积误差；跨小节、短装饰音和三连音有专项测试。

### P5：可选的合成对照实验

- [ ] 先用简单谐波合成作为试听/诊断，比较基频、发声区间与边界，而非逐采样点波形误差。
- [ ] 若 P3 仍有明确不足，再评估 DDSP 的谐波/噪声合成及多尺度频谱损失。
- [ ] 对齐全局延迟和采样率；若使用时间规整，限制范围，不能靠任意拉伸掩盖漏音或错误时值。
- [ ] 区分音符参数与音色、辅音、气声、混响；避免为拟合音色而改错音符。
- [ ] 对候选的增删、合并、拆分做离散搜索；连续参数优化只处理边界、音高等适用参数。

验收：相对 P3 有可重复的人工标注指标和盲听收益，否则不加入默认链路。
这属于独立研究阶段，不作为 P0～P4 的交付前置条件。

## 6. 评测与验收规则

主要指标采用同一套评测器、匹配规则和容差；P0 固定后不能为了某个候选临时修改。

- 音符级 precision/recall/F1：分别报告音高+起音和音高+起止时间两种匹配。
- 建议初始容差：音高 50 cents、起音 50ms、止音 max(50ms, 参考时值的 20%)；P0 结合标注精度确认。
- 单独统计漏音、多切、误合、八度错误和弱音误删，不能只报告总体 F1。
- 连续 F0 准确率、voicing 错误及起止误差，说明颤音/滑音的标注和评测口径。
- 人工盲听、每段修谱耗时及修正操作数；分不同错误类别报告，不只挑成功样例。
- CPU/GPU 资源、长音频稳定性、取消延迟及失败恢复。

质量阈值须在基线完成后、候选调参前明确写入报告；达到阈值才能更换默认引擎。
合成音频和单元测试验证工程行为，不能代替真实歌声质量评估。

## 7. 实施位置、测试与回退

预计涉及：`workers/transcription/vss_worker/` 模型适配器与结果处理，`apps/api/` 任务选项和产物接口，
`packages/contracts/` 数据契约，`apps/web/src/` 诊断/试听/导出，`scripts/` 评测脚本，以及 `docs/` 文档。
沿用现有模块，不为本轮计划额外迁移前端框架或替换人声分离模型。

每个阶段执行与改动相符的验证：

```bash
python -m ruff check apps/api workers
python -m mypy apps/api/app workers/transcription/vss_worker
python -m pytest
npm test
npm run build
```

补充模型适配器 fixture、API 契约/旧项目兼容、取消/长音频/分段边界和浏览器对照流程测试。
大型模型评测单独运行，不让普通单元测试强制联网下载权重；受环境限制的检查如实记录。

每阶段完成验收、检查工作区及暂存区差异后创建独立 Conventional Commit，再推进下一阶段。
任一新引擎或自动校验均能关闭并回退到保留的原始结果；不覆盖用户修改，不重跑已完成的分离步骤。
默认只创建本地提交，GitHub 推送和发布仍需用户另行授权。

## 8. 本轮开工顺序

P0 损失定位 → P1 小样本模型对比 → P1.5 tuning 诊断 → P3 独立 F0 校验 → P2 实验候选接入 → P4 双版本谱面。
P5 仅在前述评测显示必要时另行启动。

开始前先完成候选许可和模型环境预检；没有可复现的质量报告，不直接替换默认引擎或承诺准确率提升。
