# 五线谱渲染与简谱图片导出优化计划

日期：2026-09-10

状态：待实施

## 1. 背景

当前编辑页面中的简谱使用浏览器端自研布局，主要目标是支持选音、编辑、播放高亮和快速预览，不是出版级排版。实际使用中已经出现以下问题：

- 数字、附点、八度点、延音线和休止符的字体大小不统一；
- 符号与数字发生重叠；
- 不同音符组合的横向间距不稳定；
- 跨小节、连音和复杂节奏的可读性不足；
- 当前没有稳定的五线谱/简谱 SVG、PNG 和 PDF 导出链路。

本计划将编辑器与最终排版解耦：编辑器继续服务交互和快速修改，独立渲染器负责高质量预览和图片导出。

## 2. 目标

- 保留现有 `ScoreProject`、`ScoreNote`、音符 ID、播放高亮和编辑接口；
- 五线谱能够生成稳定、可重复的 SVG、PNG 和 PDF；
- 简谱使用统一的音乐排版坐标系统，不再依赖普通 HTML 文本流；
- 简谱数字、八度点、附点、休止符、延音线和连音线不重叠；
- 导出图片与编辑页面中的谱面数据一致，不改变演唱版、谱面版、MIDI 或 MusicXML 数据；
- 导出结果支持高分辨率打印和浏览器预览；
- 第三方渲染器无法稳定保留音符 ID 或编辑映射时，可以回退到项目内 SVG 渲染器；
- 第三方代码、字体和渲染容器的许可证能够单独审查和记录。

非目标：本计划不重新训练转谱模型，不改变 Demucs、Basic Pitch、GAME + F0 或量化算法，不把导出渲染器反向作为识别结果修正器。

## 3. 候选方案调查

### 3.1 Verovio：五线谱首选候选

官方项目：<https://github.com/rism-digital/verovio>

Verovio 是面向 MusicXML、MEI 等格式的排谱工具，适合输出 SVG，并提供 JavaScript、Python 和命令行使用方式。它更适合无头服务端渲染和保留谱面元素映射。

拟用法：

```text
ScoreProject -> 现有 MusicXML 导出 -> Verovio -> SVG -> PNG/PDF
```

进入条件：

- 能正确处理现有 MusicXML 的拍号、调号、休止符、跨小节音符和连线；
- SVG 元素能够映射回稳定的 `ScoreNote.id` 或可接受的替代映射；
- 服务端渲染耗时和内存不会阻塞普通 API 请求；
- LGPL 许可边界、动态链接方式和容器分发说明完成登记。

回退：保留现有 MusicXML 导出，使用独立的项目内 SVG 五线谱渲染器或 MuseScore 导出器。

### 3.2 MuseScore Studio：高质量离线导出候选

官方命令行文档：<https://musescore.org/en/handbook/4/command-line-usage>

MuseScore Studio 适合生成出版级五线谱，并能通过命令行导出 PDF、PNG、SVG、MusicXML 和 MIDI。它适合作为独立渲染容器或最终导出兜底，不直接作为前端编辑器核心。

优点：

- 五线谱版面和常见音乐符号质量高；
- 适合最终打印和 PDF；
- 可以作为人工验收的参考渲染器。

风险：

- 镜像和运行环境较重；
- 批量无头导出需要验证启动时间和字体一致性；
- 简谱需要插件、模板或自定义字体验证，不能假设默认输出满足需求；
- GPLv3 及相关插件、字体许可需要分别登记。

进入条件：

- 完成一条不依赖桌面会话的容器内命令行导出流程；
- 固定 MuseScore 版本和字体包；
- 对同一输入生成稳定的 SVG/PNG/PDF；
- 明确是否仅作为本地非商业导出工具，避免把未经审查的渲染镜像发布为公共镜像。

### 3.3 OpenSheetMusicDisplay：浏览器五线谱与简谱 PoC

官方项目：<https://github.com/opensheetmusicdisplay/opensheetmusicdisplay>

OSMD 是 TypeScript/JavaScript MusicXML 渲染器，适合浏览器和无头环境。项目页面列出了 Jianpu Display，但该功能目前按 early access/sponsor 方式提供，需要单独确认版本、可用性、授权和离线部署条件。

只在 PoC 中验证：

- 五线谱渲染质量；
- SVG/PNG 输出；
- 音符 ID、点击选择和播放高亮；
- Jianpu Display 是否可在本项目非商业、离线和 Docker 环境中使用；
- 是否存在功能锁定、赞助要求或额外许可。

如果简谱功能不能独立部署或不能稳定映射音符 ID，则不进入主链路。

### 3.4 LilyPond：出版级排版备选

官方文档：<https://lilypond.org/doc/v2.25/Documentation/usage/basic-command_002dline-options-for-lilypond>

LilyPond 适合出版级五线谱和严格控制版面，也能输出 PDF、PNG、SVG 等格式。它需要把项目数据转换成 `.ly` 文件，和当前 MusicXML 导出链路不同。

暂不作为第一阶段方案，只有在 Verovio 和 MuseScore 的五线谱质量无法满足打印要求时再评估。简谱需要单独设计 LilyPond 记谱和字体方案，不能作为当前简谱问题的低成本解决方案。

## 4. 推荐架构

### 4.1 数据源

继续以 `ScoreProject` 为唯一权威数据源：

```text
raw_notes             原始识别证据，不参与排版修改
performance_notes     演唱版真实毫秒时间
notes                 谱面版量化音符
MusicXML              由 notes 可重复生成
SVG/PNG/PDF           由 notes 和渲染配置可重复生成
```

导出图片默认使用谱面版 `notes`。演唱版仍只用于演唱版 MIDI、试听和对齐诊断，不把毫秒偏移错误写成谱面 BPM 或版面位置。

### 4.2 渲染服务

增加独立的 `score-renderer` 层，优先实现服务端 Verovio 适配器：

```text
API 导出请求
  -> 读取 ScoreProject
  -> 生成 MusicXML 或 JianpuLayoutModel
  -> score-renderer
  -> SVG
  -> PNG/PDF 转换
```

渲染服务不直接访问模型、音频、数据库写接口或用户编辑接口。渲染失败只返回错误，不修改项目 revision。

第一阶段可以先使用一次性容器或 Python/Node 子进程；确认性能后再决定是否常驻 Worker。不能让普通 API 请求隐式下载字体、渲染器或模型。

### 4.3 简谱排版模型

简谱不直接从 `ScoreNote` 拼接 HTML，而是增加中间布局模型：

```text
ScoreNote
  -> JianpuToken
  -> JianpuMeasure
  -> JianpuLayoutLine
  -> SVG
```

`JianpuToken` 至少需要记录：

- 稳定音符 ID；
- 数字或休止符；
- 升降号；
- 高音点、低音点；
- 附点和延音线；
- 起止拍位置和实际绘制宽度；
- 小节、行和系统位置；
- 播放高亮区域；
- 与原始 `ScoreNote` 的映射。

布局器必须先计算所有符号的包围盒和最小间距，再绘制 SVG，禁止依赖浏览器自然换行解决重叠。

## 5. 分阶段实施

### 阶段 0：许可、输入和截图基线

- [ ] 固定当前 MusicXML、MIDI 和简谱样例；
- [ ] 建立覆盖普通音符、升降号、八度点、附点、休止符、三连音、六连音、跨小节延音和重复音的 fixture；
- [ ] 保存当前 abcjs/简谱渲染截图作为对照，不把截图或构建产物提交到 Git；
- [ ] 记录 Verovio、MuseScore、OSMD、LilyPond 的版本、代码许可证、字体许可证和容器体积；
- [ ] 确认现有 MusicXML 对休止符、连音、调号和跨小节音符的表达没有数据损失。

验收：所有候选使用同一批输入，能重复生成对照结果；未引入新的模型、权重或用户音频。

### 阶段 1：五线谱 SVG/PNG/PDF

- [ ] 接入 Verovio PoC，使用现有 `project_to_musicxml()`；
- [ ] 验证拍号、调号、 tempo、休止符、跨小节音符、连线和多小节布局；
- [ ] 输出 SVG，并验证 SVG 在浏览器中非空、尺寸稳定、无裁切；
- [ ] 输出 PNG，固定 DPI/页面尺寸/透明背景策略；
- [ ] 输出 PDF，验证中文标题、字体嵌入或字体替代策略；
- [ ] 记录渲染错误、耗时、内存和并发行为；
- [ ] 为每个导出格式增加 API 测试和最小浏览器验收。

验收标准：

- 同一项目重复导出结果结构稳定；
- 页面无音符截断、重叠或异常空白；
- 导出不改变项目 revision；
- 导出失败时不会修改项目文档；
- SVG 中可定位主要音符或提供稳定的顺序映射。

回退：保留当前 MusicXML 下载；若 Verovio 不满足质量，接入 MuseScore CLI 作为独立导出器，不影响编辑页面。

### 阶段 2：简谱 SVG 排版 PoC

- [ ] 先实现独立 `JianpuLayoutModel`，不替换现有编辑器；
- [ ] 使用本地固定字体或项目内 SVG glyph，禁止依赖 Google Fonts/CDN；
- [ ] 实现统一字号、数字基线、上下八度点、附点、升降号、休止符和小节线；
- [ ] 实现延音线、连音线、跨小节拆分和最小间距；
- [ ] 支持稳定音符 ID、选中态、播放高亮和休止段指示；
- [ ] 输出 SVG 和 PNG；
- [ ] 与现有简谱渲染器建立对照页面。

验收标准：

- 数字和符号在桌面、移动端和不同缩放比例下不重叠；
- 播放高亮不改变布局尺寸；
- 音符点击、编辑、移动、删除和播放定位仍能通过原 ID 工作；
- 量化、止音建议、对齐偏移和导出数据不被渲染器改写；
- 复杂样例的截图质量明显优于当前实现。

回退：继续使用当前简谱预览；新 SVG 渲染器只作为实验导出，不影响默认界面。

### 阶段 3：第三方简谱方案评估

- [ ] 建立 OSMD Jianpu Display 的本地 PoC；
- [ ] 对比 OSMD、MuseScore 插件/模板和自研 SVG 的字体、间距、连线和音符映射；
- [ ] 验证是否需要赞助、额外授权或固定远程服务；
- [ ] 对比冷启动、批量导出、Docker 构建和离线运行成本；
- [ ] 形成选型结论，不把未验证候选写成已接入功能。

决策规则：

- 能稳定独立运行并保留音符 ID，才可进入主链路；
- 只能生成好看的静态图但无法映射音符 ID，可只用于最终导出；
- 依赖远程字体、赞助权限或无法离线构建时，不作为默认依赖；
- 自研 SVG 在交互映射和许可上更可靠时，保留自研方案。

### 阶段 4：导出接口和前端入口

- [ ] 增加五线谱 SVG/PNG/PDF 导出接口；
- [ ] 增加简谱 SVG/PNG/PDF 导出接口；
- [ ] 前端导出菜单明确“谱面版”来源；
- [ ] 导出过程中显示状态和明确错误；
- [ ] 大文件导出避免阻塞 API，可转为任务或渲染队列；
- [ ] 记录渲染器版本、字体版本、页面尺寸和配置到导出 provenance；
- [ ] 保持 MIDI/MusicXML 接口兼容。

### 阶段 5：回归、性能和文档

- [ ] 完成桌面/移动端 Playwright 验收；
- [ ] 验证 SVG 非空、PNG 可解码、PDF 可打开；
- [ ] 验证音符高亮、选中、编辑和播放时间轴一致；
- [ ] 测试 1、10、50 页谱面的渲染时间和内存；
- [ ] 测试渲染器不可用、字体缺失和格式错误时的回退；
- [ ] 更新 README、`docs/model-licenses.md`、`docs/api.md` 和 `docs/architecture.md`；
- [ ] 更新 `docs/todo.md`，关闭已完成的简谱展示待办；
- [ ] 每个阶段完成后创建独立 Conventional Commit，不推送远端。

## 6. 测试计划

### 后端

- MusicXML 输入覆盖调号、拍号、休止符、跨小节延音和多段 tempo map；
- SVG/PNG/PDF 导出响应类型、文件名和错误处理；
- 导出不修改 revision、notes、performance_notes 或 raw_notes；
- 字体和渲染器缺失时返回可识别错误；
- 同一项目重复导出结果稳定；
- 渲染任务取消和并发限制。

### 前端

- 简谱数字和符号布局不重叠；
- 音符 ID 选择、编辑和播放高亮不丢失；
- 播放中的休止段仍显示时间指示；
- SVG 导出预览与编辑页面使用同一谱面版数据；
- 移动端横向滚动、缩放和下载按钮不遮挡谱面。

### 浏览器验收

- 普通音符、附点、八度点、休止符和复杂节奏；
- 拆分、合并、移动、缩短和延长后重新排版；
- F0 止音建议接受、人工修改和 superseded 状态；
- 五线谱与简谱切换后音符 ID 和播放位置一致；
- 导出 SVG/PNG/PDF 均能打开且无空白页或裁切。

## 7. 许可和存储约束

- 不把渲染器二进制、字体包、生成图片、用户音频或模型权重提交到 Git；
- 第三方代码、插件、字体和渲染器镜像分别记录官方来源、版本、许可证和再分发条件；
- 不因为项目非商业用途就推断 GPL/LGPL/BSD/字体许可允许任意分发；
- 若使用 MuseScore 插件或 OSMD Jianpu Display，单独记录插件和功能授权；
- 导出图片是否包含第三方字体 glyph，需要在发布前确认；
- 下载链接无法联通或速度明显阻塞时，停止反复重试，记录目标文件、来源、路径和校验信息，请用户自行下载后再继续。

## 8. 推荐默认决策

第一阶段优先接入 Verovio 作为五线谱 SVG 渲染 PoC；MuseScore Studio 作为高质量离线导出和视觉对照；OSMD Jianpu Display 只做本地可用性验证；简谱主线采用独立 SVG 排版模型，不继续扩展当前 HTML 文本拼接布局。

最终采用哪一个第三方方案，必须以实际截图、音符 ID 映射、离线构建和许可证审查结果为准，不以项目宣传页或单个成功样例作为完成依据。
